### Test runs clean up their temp folders, and held asks count tidy's demo (PIE-1742)

- **A test run leaves nothing of its preloads in the temp dir:** `bun test` (1.4) never fires `exit`, so the door's state dir and the fake ssh's owner folder stayed behind after every test process. By Nov 11 float-box's `/tmp` held 445,000 of them. Bun reads every folder above a program's own when it starts one, so an extension's process under `/tmp` took 200 ms instead of 10. The preloads now remove their folders in a last `afterAll`, which runs after failed and timed-out tests too.
- **The parity scenario "board: detail" fits its 60 s budget again** once `/tmp` is swept: it walked in 47 to 49 s on a clean temp root, against 62 s under `/tmp`, with the same builds and round trips. Each key typed in the power bar's query line asks the issues extension's query source.
- **The held-asks test waits for its own held ask:** installing tidy writes its demo note, whose ask is held for r on purpose (PIE-1737). The test now finds its own row by its note and checks the demo's row too, instead of expecting exactly one.
- **`scripts/scratch-clean --old` sweeps test leftovers:** it removes this user's test folders more than a day old from `/tmp` and `/tmp/ep0ch-<uid>`, and says how many. Only the six test prefixes go: `ep0ch-test-state-*`, `fake-ssh-owner-*`, `outliner-test-no-user-extensions-*`, `ep0ch-scratch-*`, `ep0ch-fold-*` and `outliner-script-site-*`. A day is longer than any run, so a test still running keeps its folders. The leaks behind the last three are [[PIE-1744]].
- **Run:** nothing to deploy (tests and scripts only). Run `scripts/scratch-clean --old` once on float-box.
