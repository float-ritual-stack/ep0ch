### "Running twice" goes away when the other process does (PIE-1812)

- **Seen:** on Nov 19 Evan's Claude status line kept "⚠ ep0ch: running twice: pid 53128 too · ep0ch agent stop 53128 --session 86a07a61" with no other session running.
- **The cause, in the mod:** it asked `ep0ch agent splits` once, at `session.start`, and kept the answer for the life of the process. Nothing asked again, so a split that ended stayed on the line.
- **The fix, in the mod:** it asks again, and the line says what the last ask found. While the warning shows: at every prompt and at the end of every turn, once the last ask is 5 s old, so a stop run in the turn clears it there. While it doesn't: at a prompt at most every 3 minutes, so a split that starts later shows too. One ask at a time (0.6 s on float-box), and no later prompt waits for it.
- **The first prompt too:** while the warning shows it asks again and waits for that answer (1.5 s at most), so the model isn't told of a split that ended since the start. With "runs once" in hand it goes at once, and the next prompt tells the model of a split the new ask finds.
- **Sooner than the brief's "every few minutes" while the warning shows:** otherwise the line would go on saying "running twice" for minutes after the stop command it names had run.
- **No answer, no warning:** an ask again that fails or times out clears the line, as the start's always did.
- **The fix, in the door's one reader:** nothing between `claude agents` and the split decision checked that a listed pid is still a process. `scripts/agent-restart --ls` now says `alive` for each row (a signal-0 check on the machine the pid runs on, so it holds over ssh and on macOS), and `holdsSession` is the one test: a pid that has exited, and a background job listed with no pid, hold nothing. `ep0ch agent splits`, the door's `⚠ ×2` chip and `ep0ch agent stop`'s "another process still holds it" all ask it. Before, a dead row beside the one live process read as a split, and `agent stop` would have stopped the only process.
- **Red first:** the mod's `split-session.test.ts` (a split at start, then one process: the line kept the warning) and the door's `agent-fleet.test.ts` (the stopped pid still listed: still a split).
- **Not verified:** whether pid 53128 was a dead row `claude agents` still listed or a split that had ended; the laptop wasn't reachable. Both are fixed. On float-box today `claude agents` lists 6 background jobs with no pid, and leaves out the one dead pid that still has a registry file; that is one case on Linux, not proof for the Mac.
- **Run:** no PROTOCOL, GRAMMAR or schema change. `ep0ch install --apply` on each machine, the laptop first (where it was seen); a Claude session picks the mod up at its next start.
