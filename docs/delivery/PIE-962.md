# PIE-962: Loki query leases

The code adds `ep0ch loki lease --ttl 1h`, `ep0ch loki lease --revoke` (all
leases), and the authenticated gateway's `loki_lease` tool. The CLI prints only
the URL, so `export LOKI_URL=$(ssh float-2 ep0ch loki lease --ttl 1h)` works.
The tool returns `url`, `id`, and `expiresAt`. Keep the URL in the shell; it is a
bearer credential, not a link to publish in a chat preview.

The signed-in publisher accepts `/loki/<token>/loki/api/v1/…` without a browser
cookie, after its existing Host check. A trailing slash in `LOKI_URL` works with
scripts that append `/loki/api/v1/…`. Only GET query, query_range, labels,
label/<name>/values and series pass. Push, delete, tail and admin routes do not.
Upstream redirects are refused; caller cookies and headers are not forwarded.
The upstream is `http://127.0.0.1:3101` on the publisher machine.

The outline host owns expiry, revocation and the 60-queries-per-minute limit per
lease. TTL uses the existing share duration parser: default one hour, 1m–24h.
Restarting the host ends leases; restarting only the publisher does not. Requests
already admitted may finish after expiry/revocation. Host and publisher logs name
the lease id and result, never the bearer token or LogQL text. Access logs in the
outer proxies must also avoid recording the token.

Reuse: the host action dispatcher and Unix socket, the gateway's existing Clerk
admission and host admin client, the signed-in publisher's token-route boundary,
the share TTL parser and token-path log redactor. There is no separate HTTP
listener or MCP query transport. Leases are host memory, not outline content;
no schema change is needed. Service wire changes: `loki.lease.start`,
`loki.lease.revoke`, `loki.lease.use`; PROTOCOL 215 → 216 at main be168e79.
Outline-core gains response types but changes no computed result. If main moves,
the deployer must reset PROTOCOL to main plus one before merging.
