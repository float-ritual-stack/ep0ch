## Cause and repair

The JUnit and hang-report artifacts confirm a serial tail. CI gives each file one
worker (`--parallel=16`). In the slow run's hang report, about 70% of CPU was idle
while the remaining parity workers used individual cores; steal and throttling
were negligible. Increasing worker count could not shorten those six files.

The split retains every scenario exactly once. Its coverage check compares the
assigned labels with the complete scenario definitions and checks that every
worker has a test file. The desk tree still owns the global shell input-state
probes. Local state probes remain with each worker; there is no shared ledger or
new state-skipping ownership scheme.

A policy-only scratch run exposed another cost: its trace classified `h`, `j`,
`l`, arrows, Tab, Page Down and End inside the open policy panel as new input
states. The no-action branch queued a second-key walk whenever the screen held
the keys, even when it already held them before the key. It now uses the existing
`opened` condition, as the action-opening branch already did. Every first key and
click remains covered, and a prefix entered from a non-holding state still gets
its second-key walk. Navigation within the existing panel no longer causes that
incidental cross-product.

Fantasia observes frames produced by the actual stage renderer from the button
press through settlement. It no longer requires more than 20 wall-clock samples
inside a fixed-duration dance. River search waits for the actual result row
before Enter, instead of matching the query text and sleeping 400 ms. Its column
hydration wait allows 20 seconds, with a comment explaining scratch-host load.

The 720-second watchdog and 180-second quiet classification are unchanged. Both
stale "about 8" claims are removed. A replacement fast-CI duration would be an
unmeasured claim until this unpushed code runs there. No runtime behavior,
protocol, schema or showcase section changes are needed for this test/CI repair.
