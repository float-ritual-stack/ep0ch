# Review round 2: whole codebase, multi-lens (PIE-510)

Reviewed on float-2 at ep0ch-door `465f386` and pi-herdr-outliner `0f7e610`, after tonight's merges (door
#89–#101, outliner #263–#270). Six reviewers, one lens each: A architecture ("did you really use it?"),
B correctness, C agent parity and safety, D tests and dead code, E macro cohesion, F the dogfood walk's rough
edges. They reported and changed nothing. Probes were throwaway `bun test` files against scratch services
(`test/scratch.ts`) with fictional data; no real outline or door was touched.

Each finding has where, severity, how it was verified (**read**: the code path traced end to end; **ran**: a
probe reproduced it) and the fix. Findings marked *plausible* weren't reproduced. The **Status** line says
which PR fixed it, or why it's deferred.

Severity: **high** is data loss, a security hole, an agent taking the person's focus or keys, or a crash in
daily use. **Medium** is wrong behaviour a person or agent will hit, or a real parallel implementation of a
shared part. **Low** is cosmetic, dead code or a stale doc.

## Summary

**63 findings:** 2 high, 30 medium (one plausible), 31 low. Review of the fix PRs found 3 more highs, listed
under [Found while reviewing the fixes](#found-while-reviewing-the-fixes).

- **High:**
  - **B1:** "apply anyway" on a stale proposal could erase what the person wrote after an end-of-note passage.
  - **C1:** any note title, flash or extension error could write raw terminal escapes (OSC 52 clipboard
    writes, clear screen) to the person's terminal.
- **Medium:** the notable ones.
  - Floats were handled per action, so a swap lost a tile, an open beside a float made an invisible tile,
    and a dock ignored policy (B7–B9).
  - A container's policy vanished when it fell to one tile (B10).
  - The board's fixed shape lived in code, and moving the preview broke opening a detail (A1).
  - An agent could unlock a screen the person locked, and could move the tile the person was typing in with
    `tile.pin` (C3, C4).
  - The `ext:` actor namespace wasn't reserved, which let a line run as the person's request (E6, B3), and
    extension writes skipped the draft router's guard (C5).
  - The proposal lifecycle was split between the service and the door (E3).
  - "in the Trash" was missed for a note trashed with an ancestor, because the re-read decision existed in
    three copies (F6).
  - Widths were counted in code points, not cells (F7).
- **Fixed:** everything except what's listed under [Deferred](#deferred). There were 12 PRs: door
  #102–#109 and outliner #271–#274.
- **Deploy:** the outline host on float-2 runs the new service. Both outlines were backed up and checked
  first (see [Deploy](#deploy)).

## Recognised systems, round 2

- **The board is a preset now.** `DeliveryBoard extends Desk`; its lanes are query tiles in a `columns`
  container fed by a `hub:` tile source, and its drawers and floats are the desk's. No second drawer or float
  model is left in `delivery.ts`, and layout code never checks a tile kind's *name*.
- **Extension output has one door renderer**: `projection.ts` with `primitiveLines`, parity-tested against
  the service's `renderComponent`. The `::graph-*` figures are the exception (A3).
- **What's left is at the edges added tonight:** float handling decided per action (B7–B9), the board's fixed
  shape held in code rather than policy (A1), the proposal lifecycle split between the service and the door
  (E3), the `ext:` actor namespace unreserved (E6), and the terminal sink trusting every string (C1).

- **Where:** `src/desk/delivery.ts:66,75-80` (only the lanes had a policy). Shape rules were keyed on tile

## B. Correctness

### B1 "Apply anyway" erased what the person wrote after an end-of-note passage — **high**
- **Where:** outliner `src/draft-patch-compare.ts:128-143` (`locateSpanForced`), called from `src/draft-patch-router.ts:264-266`.
- **Verified:** ran (probe P1b).
- **Scenario:**
  1. An agent's stale patch of a note's last line becomes a proposal with an empty `after` context.
  2. The person rewrites that line and adds two more, then presses A.
  3. `observed` is gone and `after` is empty, so the replace runs from `before` to the end of the note.
  4. The rewrite, the embed line and both new lines are gone.
  - The forced path also ignored the mark.
  - An existing test asserted a smaller case of this.
- **Status:** fixed, outliner #271.
  - A forced apply replaces only the exact passage the proposal shows, and stays above the mark.
  - If the person changed the passage, the apply is refused and their text stays.
